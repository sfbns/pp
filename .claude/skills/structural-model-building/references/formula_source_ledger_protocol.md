# 逐式来源账本协议

## 0. 为什么

结构模型里错一个负号、少一个 `/100`、多转置一次矩阵，会让 markup、弹性和福利全盘失真，而且事后极难发现。同时"公式复杂"经常被误当成"识别更强"。账本把两件事强制分开记录：**这条式子从哪来** 与 **这条式子被识别到什么程度**。

本机实测有效：主报告 80 式、iter3 70 式、iter4 patch 15 式、iter5 78 式，全部逐条配平并通过三份独立审计。

## 1. 四类标签

| 标签 | 含义 | 举证要求 |
|---|---|---|
| **[O] source-exact** | 已重开原始文献**原页**逐字核对 | 记页码与本地页图路径。**OCR 结果只是定位器**——公式块常是图片，OCR 取不到，不算证明 |
| **[D] standard-derived** | 从明确引用的标准模型代数推导 | 写出推导链与所引原式编号 |
| **[P] project-extension** | 本项目新增设定 | 必须同时写清 primitives、单位、符号、识别矩 |
| **[I] illustrative-only** | 只作说明 | 明写"当前数据下不得声称已识别" |

账本每条至少含：`formula-id` · 标签 · 来源（文献+页 / 推导链 / 项目理由）· 单位 · 符号预期 · 识别所依赖的矩或排除限制。

**子标签 `[O·卡]`**（2026-10-07 起使用）：引用本机精读卡里已记为"原页视觉核验"、但本轮没有重新打开原页的式子。它比 `[D]` 强、比 `[O]` 弱。正式交付前要么重开原页升级为 `[O]`，要么保留子标签并在账本里写明卡片路径。

## 2. 机械验收（可脚本化）

- 标签总数 = 唯一标签数 = 账本条目数；主稿与账本**零缺失零孤儿**
- 行内数学定界符配平、行间定界符配平、`aligned` 等环境配平
- 花括号扫描零残余；无 U+FFFD 替换字符；无隐藏 CR/TAB
- Pandoc 解析 exit 0
- 冻结件出 SHA-256，**每份审计报告绑定该 SHA**

参考实现（Python）：
```python
import re, io, hashlib
t = io.open(path, encoding='utf-8').read()
tags = re.findall(r'tag\{([^}]+)\}', t)          # 或 formula-id: 注释
assert len(tags) == len(set(tags))
assert t.count(r'\[') == t.count(r'\]')
assert t.count(r'\(') == t.count(r'\)')
assert t.count(r'\begin{aligned}') == t.count(r'\end{aligned}')
assert '�' not in t
print(hashlib.sha256(open(path,'rb').read()).hexdigest().upper())
```

## 3. 经济学验收

- **导数**：先确认求导对象是**哪个备选项的效用指数**，再定符号，最后才聚合。（BLP 交叉价格导数就是靠这一步抓错的。）
- **矩阵方向**：`Δ_jr = −∂s_r/∂p_j`（行 = j 的价格 FOC，列 = r 的 margin）。若 Jacobian 存成 `J_rj = ∂s_r/∂p_j`，必须写 `Δ = −(Jᵀ ⊙ H)`。上线前用有限差分逐元核对。
- **单位与尺度**：生命周期成本要显示 `/100` 换算、能源价格单位、里程期限、折现与存活因子、转售终值；所有金额统一到同一不变价基期与同一货币尺度 `U`，实际折现率与实际价格配套。
- **重复计价**：同一现实机制不能进两次（例如既把不便写进个体效用损失、又在外面乘一个不便系数；或既用 granular 分项成本、又加一个复合展示指标）。三种等价写法**只能选一种**。
- **符号约束**：需要为正的系数用有正支持的分布（相关对数正态块），不要"线性正态抽样 + 事后截断"。
- **比率**：`E[γ/α] ≠ E[γ]/E[α]`。任何比率型对象（资本化率、WTP、货币化福利）逐个体/逐抽样算完再聚合。
- **福利不可相加**：决策 surplus 与规范经验福利回答不同问题，不能相加，也不能挑最有利的当唯一主口径。

## 4. 原文也会错：五处原文问题与三处约定差异

本机实测抓到的原文层面问题（**说明"照抄原文"不是安全做法**）：

1. **符号/下标笔误**：BLP(1995) (6.9b) 印的 `f_j(ν, ξ, …)` 应为 `f_j(ν, δ, …)`；`[∂μ_ij/∂p_q]` 应为 `[∂μ_iq/∂p_q]`，否则照抄得零。
2. **归一化与计数设计**：固定 ns 个 accepted draws 时，条件密度 q=fbar*p0/sbar，E[sum(sbar/fbar)*f_j]=ns*s_j，实现时只除 ns，绝不再除 sbar；固定 N 个 proposal draws 才用 (1/N)sum I_i*f_j/fbar，accepted 个数此时随机。旧版将两种设计混同的 ns*sbar 分母撤回。详见 blp-model-building/references/blp1995_verified_equations.md 的两式及 normalization_selftest.py。
3. **半对数百分比换算**：系数 0.267 与 −0.667 的精确百分比是 **+30.6%** 与 **−48.7%**，不是 +26.7% 与 −66.7%（`exp(b)−1`）。
其余实测：随机系数支持与符号假设冲突（要求 `β^p<0` 却用无界正态）、未来流量贴现方向写反（`ρ^{t−s}` 应为 `ρ^{s−t}`）、反事实库存递推漏折旧 `(1−d)`、消费者剩余总量与人均尺度歧义（是否乘市场规模 `M`）、Jacobian 行列方向未固定。

**2026-10-07 补充的三处"照抄会错"**（不是原文错，是约定不同）：
- Conlon & Gortmaker (2020) 式 (6) `Δ ≡ −H ⊙ ∂s/∂p` 注明 (j,k) 元为 `∂s_j/∂p_k`，与 BLP (3.4) `Δ_jr = −∂s_r/∂p_j` 差一次转置；需求 Jacobian 对称（准线性价格的混合 logit）时等价，收入规格下不等价。Miller & Weinberg (2017) 式 (9) 写的是转置后的 Jacobian，与 BLP 一致。
- Conlon & Gortmaker (2020) 式 (26) 定义 `α_i ≡ ∂u/∂p`，为负数，与 `−αp, α>0` 的写法相反；同文 p.8 脚注 17 的 `α_i` 却取正号，同一篇里两种约定并存。
- Barwick, Kwon & Li (2024) 正文把负号放在式 (8) 外、`α_i > 0`，表 3 说明却把 `α_i` 写成负指数。
另：本机 BLP walkthrough 的 (6.9b) 漏负号已于 2026-10-07 在全部 8 份副本中修正，记录在 `D:\blp-structural-skill-config\VERIFICATION_LEDGER.md` G 节。

**2026-10-07 历史纠错记录与当前来源边界**：下列两项不能合并为作者已确认勘误；T4、T5只检验明确给定定义下的内部代数/表格复现，不认证作者计算代码、原式出处或全文阅读：
4. **符号笔误**：Alé-Chilet, Chen, Li & Reynaert (2026, ReStud) 定义 `S_jh = −∂s_h/∂p_j`，却印 `mc = p + (Ω⊙S)^{-1}s`；在该定义下正确是减号，照抄会得 mc > p。
5. **[O] 原印式与 [D] suspected-typo诊断**：GHvB 2019 NBER工作稿PDF50/刊p48脚注26印 `ΔP + ΔP·ΔQ/η_D`，不能复现PDF52/刊p50 TableD.1；未核作者勘误、代码或唯一修复。`ΔWTP ≈ ΔP − P_0·(ΔQ/Q)/η_D` 是局部平行需求与相应供给条件下的[D]换算；`Loss=−signed ΔWTP` 是项目符号归一，非正式在线附录D.3已核原式。正式Table7以P0=24,500重算，工作稿TableD.1以推断的post-price P1=24,206重算，不可把后者叫工作稿改革前P0。D.1负斜率γ_src与D.4正比率v也须分别登记。完整目标页/未核边界见 `blp-model-building/references/extension_genealogy.md` B1。
教训：**用原始数值表做独立复现**可以定位定义、量纲或排印不一致，却不能唯一反推作者原式或升级为作者确认勘误；账本必须分开原页[O]、条件推导[D]、版本与未核项。

**处理方式**：把发现写进"本轮发现的原文公式问题：禁止照抄"一节，说明是原页错误还是 OCR 错误，并给出改正后的式子与理由。**在没有作者代码可对照时，只说"存在归一化/尺度歧义"，不武断说其数值一定错。**

## 5. 冻结与审计绑定

定稿后：计算 SHA-256 → 记录字节数与行数 → 让每一份独立审计报告在开头写明所审对象的 SHA → 审计结论用三级（FATAL / MAJOR / MINOR）并记录"未解决"数量。

**交付里必须显式写这一句**：
> 审计通过只表示公式与设计边界通过，不表示已经用数据完成估计；公式内部正确不等于其排除限制或经验解释为真。
